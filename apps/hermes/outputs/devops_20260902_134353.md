🔴 **ALERTA CRÍTICA DE INFRAESTRUCTURA**

**Estado del Sistema:** 🔴 Crítico  
**Incidente:** Fallo de acceso al motor / binario de Docker (`[Errno 2] No such file or directory: 'docker'`).

---

### 📋 Diagnóstico Inicial
El entorno desde el cual estoy ejecutando comandos no puede localizar el ejecutable de `docker` en la variable de entorno `$PATH`, o bien el socket/demonio de Docker no está accesible en el contexto actual.

### 🔍 Hipótesis Principales:
1. **Docker CLI no instalado/no en PATH:** El binario `docker` no está instalado en el contenedor/entorno donde corre el agente.
2. **Docker Socket no montado:** Si este agente corre dentro de un contenedor Docker (Docker-in-Docker o passthrough), el socket `/var/run/docker.sock` o el CLI no fueron pasados al contenedor.
3. **Servicio detenido en el Host:** El demonio `dockerd` o el servicio de Docker en el VPS está caído (`systemctl status docker`).

---

### 🛠️ Plan de Acción Recomendado (SRE Diagnostic Protocol)

Para diagnosticar y restablecer el control sin comprometer la producción:

1. **Verificar ubicación del binario en el entorno:**
   ```bash
   which docker || find / -name docker 2>/dev/null
   ```
2. **Verificar el estado del servicio en el host (si hay acceso al sistema base):**
   ```bash
   sudo systemctl status docker
   ```
3. **Verificar permisos y existencia del socket de Docker:**
   ```bash
   ls -la /var/run/docker.sock
   ```

> ⚠️ *Recordatorio de Guardrails:* Mantengo la política de **cero cambios destructivos** sin confirmación explícita. Por favor, verifica los permisos de ejecución del entorno del agente para restablecer el monitoreo 24/7.
