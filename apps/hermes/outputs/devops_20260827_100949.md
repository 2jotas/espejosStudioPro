**🟡 Estado actual de los contenedores – No se puede consultar**

| Ítem | Resultado |
|------|-----------|
| **Comando solicitado** | `docker ps` (o `docker compose ps`) |
| **Respuesta del agente** | `Error querying docker: [Errno 2] No such file or directory: 'docker'` |
| **Interpretación** | El binario **docker** no está disponible en el entorno donde se está intentando ejecutar la consulta. Puede deberse a una de estas causas: <br>1️⃣ Docker no está instalado en la máquina actual.<br>2️⃣ La variable `PATH` no incluye la ubicación de `docker` (normalmente `/usr/bin/docker` o `/usr/local/bin/docker`).<br>3️⃣ Se está ejecutando el agente dentro de un contenedor/sandbox sin acceso al socket de Docker del host. |

---

## 📋 Plan de Impacto para restaurar la visibilidad

| Paso | Acción | Riesgo | Verificación |
|------|--------|--------|--------------|
| **1** | **Confirmar que Docker está instalado**: `which docker` o `docker --version`. | Ninguno (solo lectura). | Salida debe contener la ruta del binario y la versión. |
| **2** | **Revisar el servicio Docker**: `systemctl status docker` (en host Linux) o `service docker status`. | Ninguno (solo consulta). | Debería mostrar `active (running)`. |
| **3** | **Asegurar que el usuario actual está en el grupo `docker`**: `groups $USER`. | Ninguno. | El grupo `docker` debe aparecer en la lista. |
| **4** | **Verificar el socket**: `ls -l /var/run/docker.sock`. | Ninguno. | Debe existir y ser accesible (`srw-rw----`). |
| **5** | **Ejecutar el comando de estado**: `docker ps -a` o `docker compose ps`. | Posible carga ligera en Docker (lectura). | Listado de contenedores con columnas `NAME`, `STATUS`, `PORTS`. |
| **6** | **Si el paso 5 falla**, revisar logs de Docker: `journalctl -u docker -n 50`. | Ninguno. | Mensajes de error que indiquen por qué Docker no responde. |

> **Nota de seguridad**: Ningún paso anterior modifica el estado de los contenedores; todos son **operaciones de solo‑lectura**. No se expone ni manipula ningún secreto.

---

## ✅ Próximos pasos recomendados

1. **Ejecute los pasos 1‑4** en la máquina donde normalmente controla los contenedores (ejemplo: su servidor de producción o su workstation).  
2. Si Docker **no está instalado**, instálelo siguiendo la guía oficial de Docker para su distribución (Ubuntu, Debian, etc.).  
3. Si Docker está instalado pero **no está activo**, inícielo: `sudo systemctl start docker`.  
4. Si el usuario no pertenece al grupo `docker`, añádalo: `sudo usermod -aG docker $USER` y **re‑inicie sesión**.  
5. Tras confirmar que Docker funciona, vuelva a solicitar el **estatus** o ejecute `docker compose ps` directamente.
