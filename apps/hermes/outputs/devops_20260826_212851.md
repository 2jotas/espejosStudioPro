## 1️⃣ ¿Dónde guardar PDFs, videos y enlaces?

| Opción | Ventajas | Desventajas / Riesgos | Recomendación |
|--------|----------|----------------------|---------------|
| **Enlaces a OneDrive** (o cualquier cloud externo) | - No inflas el repositorio.<br>- Escalabilidad y ancho de banda gestionados por el proveedor.<br>- Permite control de permisos y expiración de URLs. | - Dependencia de un tercero.<br>- Necesitas generar URLs firmadas o públicas.<br>- Posible latencia para usuarios finales. | ✅ **Ideal** si los archivos son pesados (> 50 MB) o si el número de recursos crece rápidamente. |
| **Git (directo)** | - Todo el código y los recursos están versionados en un único lugar.<br>- Fácil de clonar y desplegar. | - Git no está pensado para archivos binarios grandes.<br>- Cada commit aumenta el tamaño del repo y ralentiza los clones.<br>- Límite de 100 MB por archivo en GitHub. | ❌ No recomendado para videos o PDFs de más de unos pocos MB. |
| **Git LFS** (Large File Storage) | - Permite versionar archivos grandes sin inflar el repo.<br>- Integración transparente con Git. | - Necesita un plan de almacenamiento en GitHub (quota).<br>- Aún así no es tan barato como un bucket de cloud.<br>- Añade complejidad al CI/CD. | ⚠️ Viable solo si la cantidad total de archivos es limitada y deseas versionado estricto. |
| **Bucket S3‑compatible (ej. Wasabi, DigitalOcean Spaces) + CDN** | - Altísima disponibilidad y velocidad.<br>- Control de políticas de acceso (signed URLs).<br>- Costos por uso y fácil integración con Docker. | - Requiere configuración de credenciales y política de seguridad.<br>- Dependencia de otro proveedor. | ✅ Excelente opción para producción; combina bien con Nginx como reverse‑proxy estático. |

**Recomendación concreta**  
1. **Mantén los PDFs y videos en OneDrive o, preferiblemente, en un bucket S3‑compatible** y genera URLs públicas o firmadas según el nivel de confidencialidad.  
2. **Guarda solo los enlaces** (JSON o CSV) dentro del repositorio para que la aplicación los consuma.  
3. **Evita subir archivos pesados a Git**; solo usa Git LFS si absolutamente necesario y con un control de cuota estricto.
