## 1. Visión General del Sistema “Auto‑EspejosStudio”

| **Componente** | **Función** | **Tecnología Sugerida** | **Dónde se aloja** |
|----------------|-------------|--------------------------|---------------------|
| **Ingesta de datos** | Precio y profundidad de mercado, datos macro‑económicos, eventos corporativos, CRM (clientes) | *Python 3.11* + *CCXT* (cripto), *IB‑insync* (renta variable), *Alpha Vantage / FRED* (macro) | Contenedor Docker → **AWS ECS / Azure Container Apps** |
| **Persistencia** | Historicos de tick, series temporales, configuraciones, logs, métricas de performance | *PostgreSQL* (timeseries extension **TimescaleDB**) + *Redis* (caches en tiempo real) | RDS (o Azure PostgreSQL) + ElastiCache (Redis) |
| **Core de señal** | Generación de señales, back‑testing, optimización de parámetros, gestión de riesgo | *Python* (pandas, numpy, ta‑lib, vectorbt, backtrader) | Contenedor Docker, ejecutado como **Worker** (Celery) |
| **Orquestación** | Scheduler, control de flujos, re‑intentos, alertas | *Apache Airflow* (Docker‑Compose) o *Prefect Cloud* (serverless) | ECS / Azure Container Instances |
| **Ejecutores (Bots)** | Envío de órdenes a broker/exchange, control de posición, aplicación de Kelly/Fixed‑Fraction | *Python* + *CCXT* / *IB‑insync* + *REST* + *WebSocket* | Worker Docker (alta disponibilidad) |
| **API de servicio** | Exponer datos, recibir configuraciones, generar PDFs de reportes | *FastAPI* (async) con autenticación JWT | ECS (service) |
| **Front‑End / Dashboard** | UI para parametrizar, monitorizar métricas, alerts en tiempo real | *React* + *TypeScript* + *Chart.js / Plotly* + *Material‑UI* | S3 (static site) + CloudFront (CDN) → **auto.espejosstudio.cl** |
| **Alertas & Notificaciones** | Slack, Telegram, Email, webhook | *Celery Beat* + *SMTP* / *Slack API* | Worker Docker |
| **Seguridad** | Vault de secretos, rotación de claves, auditoría | *HashiCorp Vault* o *AWS Secrets Manager* | Centralizado, accesible sólo por servicios internos |

## 2. Flujo de Trabajo “End‑to‑End”

```mermaid

    A[Ingesta] --> B[Persistencia]
    B --> C[Core de Señal]
    C --> D[Orquestación (Scheduler)]

    E --> F[Broker / Exchange]
    F --> G[Confirmación / Fill]
    G --> H[Persistencia (Trade Log)]
    H --> I[Dashboard / API]
    I --> J[Usuario (auto.espejosstudio.cl)]
    D --> K[Alertas (Slack/Telegram)]
    style A fill:#f9f,stroke:#333,stroke-width:2px
    style J fill:#bbf,stroke:#333,stroke-width:2px
```

1. **Ingesta** – Cada minuto (o según intervalo configurado) se descargan:  
   - *Order‑book* y *trade* de **BTC‑USD** (Binance, Coinbase Pro) → `price, volume, bid/ask`.  
   - *Indicadores macro* (Fed Funds, CPI, NFP) via **FRED / TradingEconomics**.  
   - *Eventos de earnings* via **Yahoo Finance** API.  
   - *CRM* → se verifica la tabla `Client`; si falta, se crea automáticamente (ver apartado “Gestión de errores”).  

2. **Persistencia** – Los datos se insertan en TimescaleDB (particionado por día). Un *stream* a Redis permite cálculos de latencia < 200 ms.  

3. **Core de Señal** – Cada ciclo se ejecuta la **estrategia de “Liquidity‑Pool + RSI‑MACD”**:  
   - RSI (14) > 65 y < 75 → zona neutral‑sobrecompra.  
   - MACD crossover (línea señal) → confirmación de impulso.  
   - Identificación de *order‑blocks* (últimos 3 candle de alta/ baja con volumen > 2 σ).  
   - **Filtro de liquidez**: 1 % del *ASK*‑size debe estar disponible a menos de 0.3 % del precio actual.  
   - Si se cumplen, se genera señal *Long* o *Short* con **entry** = price + 0.1 % (slippage buffer).  

4. **Gestión de Riesgo** – Para cada señal se calcula:  
   - **Risk‑to‑Reward (RR)** = (TP‑Entry) / (Entry‑SL).  
   - **Kelly Criterion** (p = win‑rate estimado 55 %, b = RR) → % de capital a arriesgar.  
   - **Máximo Drawdown** permitido = 5 % del equity.  
   - **Stop‑Loss** = 0.8 % del precio de entrada (o nivel de soporte técnico más próximo).  
   - **Take‑Profit**: 2 × SL (RR = 2) y adicional TP2 = 3 × SL (trailing).  

5. **Orquestación** – Airflow DAG “daily_trading” lanza:  
   - `ingest_data >> compute_signals >> evaluate_risk >> place_order`.  
   - Re‑intentos y alertas automáticas si falla cualquiera de los pasos.  

6. **Ejecutor (Bot)** – Conecta a la API del broker (por ejemplo **Binance Futures** o **Interactive Brokers**) mediante **API‑Key/Secret** almacenados en Vault. Envía orden **limit** con *post‑only* y *reduce‑only* flags.  

7. **Dashboard** – En **auto.espejosstudio.cl** el usuario ve:  
   - **Panel de Control** con sliders para: `RSI‑Upper/Lower`, `MACD Fast/Slow`, `Risk % per trade`, `Max Drawdown`.  
   - **Tabla de Señales** (fecha, activo, entry, SL, TP1, TP2, RR, %Capital).  
   - **Gráficos en tiempo real** (price + EMA20/50/200, order‑block zones, volume heatmap).  
   - **Métricas de Performance**: Win Rate, Sharpe, Profit Factor, Max DD, Equity Curve.  

8. **Alertas** – Cuando se genera una señal, se dispara:  
   - Slack channel “#trading‑signals”.  
   - Telegram bot “@EspejosTrader”.  
   - Email con PDF del “Trade Ticket”.  

9. **Post‑Trade Analytics** – Cada 15 min se recalcula la *Equity Curve* y se actualiza el dashboard. Si el **drawdown** supera el umbral configurado, se envía una alerta crítica y el motor desactiva nuevas entradas hasta revisión manual.
