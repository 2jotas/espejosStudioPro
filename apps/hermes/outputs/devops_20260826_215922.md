## 1️⃣ Pasos inmediatos para re‑establecer Docker

| Acción | Comando | Comentario |
|-------|---------|------------|
| **1. Verificar instalación** | `which docker`  <br> `docker --version` | Si no devuelve ruta o versión, Docker no está instalado o no está en `$PATH`. |
| **2. Instalar Docker (si falta)** | ```bash<br>curl -fsSL https://get.docker.com -o get-docker.sh<br>sh get-docker.sh<br>``` | Script oficial de Docker CE. Después de la instalación, reinicia la sesión o ejecuta `exec $SHELL`. |
| **3. Iniciar el daemon** | `sudo systemctl start docker` <br> `sudo systemctl enable docker` | Asegura que el servicio arranque automáticamente. |
| **4. Verificar estado del daemon** | `sudo systemctl status docker` | Debería mostrarse `active (running)`. |
| **5. Añadir tu usuario al grupo `docker` (opcional)** | `sudo usermod -aG docker $USER` <br> `newgrp docker` | Evita usar `sudo` en cada comando. |
| **6. Probar un contenedor de prueba** | `docker run --rm hello-world` | Confirma que Docker puede descargar y ejecutar imágenes. |

> **Nota:** Si el VPS está detrás de Tailscale, asegúrate de que la interfaz `tailscale0` tenga acceso a los puertos Docker (`/var/run/docker.sock`). No hay restricciones de firewall a nivel de red privada que impidan la comunicación local.

## 2️⃣ Verificación de salud de los contenedores (una vez Docker operativo)

Ejecuta los siguientes comandos (o solicita que los ejecute el agente con acceso al VPS) y comparte la salida:

```bash
# Lista de contenedores y su estado
docker ps -a --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

# Healthchecks definidos en los Dockerfiles / Compose
docker inspect --format='{{json .State.Health}}' <container_name>
```

Interpretación rápida:

- **🟢** `healthy` o `Up X minutes` sin errores.
- **🟡** `unhealthy` o `Restarting` → necesita revisión de logs.
- **🔴** `Exited` o `dead` → acción inmediata (re‑deploy, revisión de configuraciones).
