## 1️⃣ Solucionar el error de Docker

El mensaje indica que el binario `docker` no está presente o que el socket del daemon no es accesible. Siga estos pasos **en el VPS** (acceso vía SSH en la red privada de Tailscale `100.93.160.96`):

```bash
# 1. Verificar si Docker está instalado
which docker || echo "docker no está en el PATH"

# 2. Instalar Docker (Ubuntu/Debian)
sudo apt-get update
sudo apt-get install -y \
    ca-certificates \
    curl \
    gnupg \
    lsb-release

# Añadir el repositorio oficial
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
    | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# 3. Iniciar y habilitar el daemon
sudo systemctl enable --now docker

# 4. Verificar
docker version
docker info
```

> **⚠️** Si el VPS usa otra distribución (CentOS, Rocky, etc.), ajuste los comandos según la documentación oficial de Docker.

Una vez el daemon esté activo, vuelva a ejecutar `docker ps` desde la sesión de usuario que emplea el orquestador (normalmente el mismo que corre `docker-compose`). Si sigue sin poder acceder, añada el usuario al grupo `docker`:

```bash
sudo usermod -aG docker $USER
newgrp docker   # refrescar sesión
```

## 2️⃣ Preparar la arquitectura de carpetas para “ramos y contenido”

### 2.1. Estructura de directorios propuesta (mirada desde el host)

```
/opt/espejosStudioPro/
│
├─ data/
│   ├─ ramos/
│   │   ├─ ramo-01/
│   │   │   ├─ index.md
│   │   │   ├─ syllabus.pdf
│   │   │   └─ recursos/
│   │   ├─ ramo-02/
│   │   │   └─ …
│   │   └─ …
│   └─ assets/          # imágenes, videos, etc.
│
├─ web/                 # código React (build)
│   └─ static/
│       └─ ramos/       # <-- se generará dinámicamente
│
├─ api/
│   └─ src/
│       └─ routes/
│           └─ ramos.ts   # endpoint que lee la carpeta `data/ramos`
│
└─ docker-compose.yml
```

### 2.2. Cómo exponer la jerarquía en la aplicación React

1. **Backend (Fastify)**  
   - Crear un endpoint `GET /ramos` que recorra `data/ramos` y devuelva un JSON con la siguiente forma:

   ```json
   [
     {
       "slug": "ramo-01",
       "title": "Nombre del ramo",
       "files": [
         {"name": "index.md", "type": "markdown"},
         {"name": "syllabus.pdf", "type": "pdf"},
         {"name": "recursos", "type": "folder"}
       ]
     },
     …
   ]
   ```

   - Si necesita servir archivos estáticos (`.pdf`, imágenes), registre un **static handler**:

   ```ts
   fastify.register(require('@fastify/static'), {
     root: path.join(__dirname, '../../data'),
     prefix: '/static/',   // <--- URL accesible desde el front
   });
   ```

2. **Frontend (React)**  
   - Al montar la aplicación, haga `fetch('/api/ramos')` y genere la navegación basada en la respuesta.
   - Para cada recurso, utilice la ruta `/static/ramos/{slug}/{nombreArchivo}`.  
   - Cuando el alumno añada un nuevo “ramo” en el host, el backend lo detectará automáticamente la próxima petición (no se requiere rebuild).

3. **Watcher opcional (dev only)**  
   - En desarrollo, puede añadir `nodemon` o `chokidar` para reiniciar el API cuando cambie la estructura de carpetas, pero en producción el endpoint es *stateless* y solo lee el FS en cada request, por lo que no necesita reinicio.

### 2.3. Docker‑compose (ejemplo mínimo)

```yaml
version: "3.9"

services:
  gateway:
    image: nginx:alpine
    ports:
      - "8080:80"
      - "8443:443"
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
      - ./web/build:/usr/share/nginx/html:ro
    depends_on:
      - api
    networks:
      - internal

  api:
    build: ./api
    environment:
      - NODE_ENV=production
      - DATA_PATH=/app/data
    volumes:
      - ./data:/app/data:ro
    networks:
      - internal

  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    volumes:
      - pgdata:/var/lib/postgresql/data
    networks:
      - internal

  redis:
    image: redis:7-alpine
    networks:
      - internal

networks:
  internal:
    driver: bridge

volumes:
  pgdata:
```

- **Nota de seguridad**: los volúmenes que contienen `data/` están montados como **solo‑read** (`:ro`). De esa forma, la aplicación solo sirve contenido, nunca lo modifica.

## 3️⃣ Próximos pasos operacionales

1. **Reactivar Docker** (pasos del punto 1).  
2. **Reconstruir y levantar los contenedores**:

   ```bash
   cd /opt/espejosStudioPro
   docker compose up -d --build
   ```

3. **Validar** que cada servicio muestre 🟢:

   ```bash
   curl -s http://localhost:8080   # Nginx
   curl -s http://localhost:3000/api/ramos   # Fastify (puerto definido en Dockerfile)
   ```

4. **Prueba de contenido**: cree una carpeta `data/ramos/prueba` con un `index.md` y verifique que aparezca en la UI sin redeploy.

5. **Aprobación de despliegue**: una vez que los servicios estén 🟢 y la prueba de contenido sea exitosa, envíe el siguiente mensaje al bot de Telegram (ID del bot configurado en `VAULT_TELEGRAM_BOT_TOKEN`) con el comando:

   ```
   /approve_deploy production
   ```

   – Esto disparará el pipeline CI/CD que ejecuta `docker compose -f production.yml up -d` en el entorno productivo.
