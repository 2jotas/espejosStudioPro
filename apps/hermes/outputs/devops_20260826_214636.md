## 2️⃣ Configurar el **GitHub Actions** (CI)  

Edita o crea el archivo **`.github/workflows/ci.yml`** en el repo `2jotas/espejosStudioPro` (o el repo correspondiente).  

```yaml
name: CI / Deploy

on:
  push:
    # Sólo se disparará cuando haya cambios dentro de la carpeta objetivo
    paths:
      - 'src/universidad/**'
      - '.github/workflows/**'   # (opcional) para que cambios en el workflow también lo disparen
  pull_request:
    paths:
      - 'src/universidad/**'

jobs:
  lint-test-build:
    runs-on: ubuntu‑latest
    steps:
      - uses: actions/checkout@v3
      - name: Set up Node
        uses: actions/setup-node@v3
        with:
          node-version: '20'
      - name: Install deps
        run: npm ci
      - name: Linter
        run: npm run lint            # <-- asegura que tu proyecto tenga eslint/prettier
      - name: Unit tests
        run: npm test                # <-- cubre coverage > 80 %
      - name: Build (React)
        run: npm run build          # <-- genera /build
      - name: Docker build & push
        env:
          REGISTRY: ghcr.io
          IMAGE: ${{ github.repository }}:latest
        run: |
          docker build -t $REGISTRY/$IMAGE .
          echo ${{ secrets.GITHUB_TOKEN }} | docker login $REGISTRY -u ${{ github.actor }} --password-stdin
          docker push $REGISTRY/$IMAGE
```

> **⚙️ Qué hace:**  
> - Sólo se ejecuta si hay commits que modifican `src/universidad/**`.  
> - Ejecuta linters, pruebas unitarias y compila la web.  
> - Publica la imagen Docker en GHCR (o tu registro privado).

## 3️⃣ Añadir la carpeta al **watcher interno** (orquestador)  

En el VPS usamos un pequeño script de *inotify* (Linux) que notifica a nuestro **gateway Nginx → API Fastify** cuando hay una nueva imagen disponible.  

**Archivo:** `/opt/orquestador/watch_folder.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

# Ruta absoluta de la carpeta que queremos monitorizar
WATCH_DIR="/home/ubuntu/repos/espejosStudioPro/src/universidad"

# Comando que se ejecuta al detectar cambios
DEPLOY_CMD="curl -X POST -H \"Authorization: Bearer ${TELEGRAM_BOT_TOKEN}\" \
           -d '{\"chat_id\": \"${TELEGRAM_CHAT_ID}\", \"text\": \"🔔 Cambio detectado en ${WATCH_DIR}. Aprobar despliegue?\"}' \
           https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage"

inotifywait -m -r -e modify,create,delete "$WATCH_DIR" |
while read -r event file; do
  echo "$(date +'%Y-%m-%d %H:%M:%S') – $event en $file"
  $DEPLOY_CMD
done
```

- **Instalación**:  

```bash
sudo apt-get install -y inotify-tools
chmod +x /opt/orquestador/watch_folder.sh
nohup /opt/orquestador/watch_folder.sh > /var/log/watch_folder.log 2>&1 &
```

- El script envía un mensaje a Telegram cada vez que detecta un cambio.  
- Cuando el operador haga “✅ Aprobar”, nuestra API Fastify llama a `docker compose up -d --pull` y redeploya los contenedores.

## 4️⃣ Seguridad y buenas prácticas  

| Ítem | Acción | ✅ / ⚠️ / ❌ |
|------|--------|--------------|
| **Variables .env** | Todas las credenciales (`TELEGRAM_BOT_TOKEN`, `POSTGRES_PASSWORD`, `REDIS_PASSWORD`) deben estar en los archivos `.env` del repo **marcados como “protected”** en GitHub y **no** deben aparecer en el código. | ✅ |
| **Linters** | `eslint` + `prettier` configurados en `package.json`. El job `lint` falla el pipeline si hay errores. | ✅ |
| **Pruebas unitarias** | Cobertura mínima 80 % (`npm run test:coverage`). El job falla si no se alcanza. | ✅ |
| **Imágenes Docker** | Usa `--pull` en `docker compose up` para garantizar que siempre se despliegue la última imagen. | ✅ |
| **Tailscale** | El acceso al VPS está restringido a la subred `100.93.160.96/32`. Asegúrate de que el agente Tailscale esté corriendo (`tailscale status`). | ✅ |
| **Healthchecks** | Cada contenedor tiene healthcheck en `docker-compose.yml`. Si alguno falla, el orchestrador marca 🔴 y envía alerta por Telegram. | ✅ |

## 6️⃣ Resumen de pasos para que la carpeta esté bajo vigilancia  

1. **Crear / actualizar** `.github/workflows/ci.yml` con el `paths` correcto.  
2. **Commit** y **push** a `main` (o la rama que uses).  
3. **Ejecutar** (o reiniciar) el script `watch_folder.sh` en el VPS.  
4. **Probar** cambiando un archivo dentro de `src/universidad`; deberías recibir un mensaje de Telegram.  
5. **Aprobar** el despliegue con el botón de “✅ Aprobar” (o enviando “/ok” al bot).  
6. La API Fastify hará `docker compose pull && docker compose up -d`; los contenedores se reinician sin downtime (rolling update).
