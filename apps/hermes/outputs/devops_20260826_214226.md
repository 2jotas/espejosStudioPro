**Rclone en nuestro entorno de producción**

---

### 📌 ¿Para qué lo usamos?
- **Back‑up de volúmenes críticos** (Postgres, Redis, archivos estáticos del front) hacia un bucket S3 compatible (Backblaze B2, AWS S3, Google Cloud Storage, etc.).
- **Sincronización** de artefactos entre el VPS y la máquina de desarrollo cuando trabajamos offline o en entornos con ancho de banda limitado.
- **Restauración rápida** en caso de corrupción de datos o despliegue fallido.

---

## 1️⃣ Configuración básica (una sola vez)

```bash
# Instalar rclone (en el VPS y en tu workstation)
curl https://rclone.org/install.sh | sudo bash

# Iniciar wizard interactivo
rclone config
```

Dentro del wizard:

| Paso | Acción | Comentario |
|------|--------|------------|
| `n`  | New remote | Nombre: `prod-backup` |
| Tipo | Selecciona tu proveedor (e.g. `s3`) |
| Endpoint | `https://s3.amazonaws.com` (o tu endpoint B2) |
| Access key / Secret key | Usa **variables de entorno protegidas** (`RCLONE_ACCESS_KEY`, `RCLONE_SECRET_KEY`) en el `.env` del contenedor. |
| Region, ACL, etc. | Ajusta según política de retención. |
| `y`  | Confirmar | Guarda la configuración. |

> **Importante:** Las credenciales nunca deben estar hard‑codeadas. Añade las variables a `docker-compose.env` y marca el archivo como **protected** en GitHub (`git update-index --assume-unchanged .env`).

## 2️⃣ Integración con Docker‑Compose

```yaml
services:
  rclone:
    image: rclone/rclone:latest
    container_name: rclone_backup
    restart: unless-stopped
    environment:
      - RCLONE_CONFIG_PASS=${RCLONE_CONFIG_PASS}   # opcional: cifrado del config
      - RCLONE_LOG_LEVEL=INFO
    volumes:
      - ./rclone.conf:/config/rclone/rclone.conf:ro   # copia tu config (sin credenciales)
      - /var/lib/postgresql/data:/data/postgres:ro
      - /var/lib/redis:/data/redis:ro
      - ./backups:/backups
    command: >
      sync /data/postgres prod-backup:postgres-$(date +%Y-%m-%d_%H-%M)
```

- **Network:** el contenedor `rclone` se une a la red interna de Docker (`espejos_net`) y, por ende, tiene acceso a los volúmenes de Postgres y Redis.
- **Tailscale:** si el VPS está conectado a la red privada (`100.93.160.96`), el contenedor hereda la ruta y no necesita reglas de firewall extra.

## 3️⃣ Cron de backups (Docker + host)

### Opción A – **Docker‑Cron**
```yaml
  rclone:
    ...
    entrypoint: ["sh", "-c"]
    command: |
      while true; do
        rclone sync /data/postgres prod-backup:postgres-$(date +%Y-%m-%d_%H-%M)
        rclone sync /data/redis   prod-backup:redis-$(date +%Y-%m-%d_%H-%M)
        sleep 86400   # 24 h
      done
```

### Opción B – **Host cron** (más flexible)
```bash
# /etc/cron.d/rclone_backup
0 2 * * * root docker exec rclone_backup \
  rclone sync /data/postgres prod-backup:postgres-$(date +\%Y-\%m-\%d_\%H-\%M)
```

> **⚠️ Aviso:** Si usas `cron` del host, verifica que el contenedor esté **🟢 running** antes de ejecutar; de lo contrario, el job fallará.

## 4️⃣ Verificación y monitoreo

| Métrica | Herramienta | Umbral |
|---------|-------------|--------|
| Último backup exitoso | `rclone ls prod-backup:` | < 24 h |
| Tamaño del backup | `rclone size prod-backup:` | Crecimiento razonable (< 10 %/día) |
| Logs de rclone | Docker logs (`docker logs rclone_backup`) | Sin `ERROR` ni `WARN` en 24 h |

Puedes exportar estos valores a **Prometheus** usando el exporter `rclone_exporter` y visualizarlos en Grafana con los siguientes alerts:

```yaml
- alert: RcloneBackupFailed
  expr: increase(rclone_backup_success_total[1h]) == 0
  for: 10m
  labels:
    severity: critical
  annotations:
    summary: "No se ha completado ningún backup en la última hora"
    description: "Revisa el contenedor rclone (docker logs rclone_backup) y la conectividad al bucket."
```

## 5️⃣ Proceso de despliegue con aprobación vía Telegram

1. **Pull Request** → CI ejecuta:
   - `rclone version` (verifica que la versión sea ≥ 1.62 para compatibilidad con `--fast-list`).
   - Linter de `rclone.conf` (evita espacios en blanco y claves sin cifrar).
2. **Bot de Telegram** (`@DeployGateBot`) envía mensaje:
   ```
   📦 PR #42 listo para producción.
   ✅ Tests: ✔️
   🔐 Secrets: ✔️
   📁 rclone config: ✔️
   👉 Pulsa "✅ Deploy" para autorizar.
   ```
3. Tras el click, el pipeline:
   - Despliega `docker-compose up -d --no-deps rclone` en producción.
   - Ejecuta un **backup inmediato** (`rclone sync ...`) antes de cualquier migración de base de datos.
   - Marca la ejecución como **🟢 Saludable** en el dashboard.
