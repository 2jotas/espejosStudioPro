## 1. ¿Git? ¿Demasiado pesado?

- **Ventajas**: historial de cambios, control de versiones, fácil de integrar con CI/CD.  
- **Desventajas**: cada *push* crea un nuevo commit; no es ideal para subir archivos grandes o para una sincronización “en tiempo real” de contenido estático (imágenes, PDFs, etc.).  
- **Conclusión**: usar Git solo tiene sentido si necesitas versionado y despliegues controlados. Para simplemente “arrastrar‑y‑soltar” y que el sitio se actualice al instante, hay opciones más ligeras.

## 2. Soluciones de sincronización en la nube

| Herramienta | Integración nativa | Configuración | Latencia / Fiabilidad | Comentario |
|-------------|-------------------|---------------|-----------------------|------------|
| **Google Drive (Rclone)** | No nativa, pero Rclone lo soporta | `rclone config` → crear remote `gdrive` | Muy buena (API de Google) | Ideal si ya usas G‑Suite. |
| **Microsoft OneDrive (Rclone)** | No nativa, Rclone lo soporta | `rclone config` → remote `onedrive` | Buena, pero a veces limita el número de peticiones | Útil si tu entorno está en Office 365. |
| **Dropbox (Rclone)** | No nativa, Rclone lo soporta | `rclone config` → remote `dropbox` | Excelente, pero espacio limitado en plan gratuito | Muy sencillo de usar. |
| **Syncthing** | P2P, sin nube | Instalar en PC y en VPS, crear “folder share” | Tiempo real, sin depender de terceros | Perfecto para entornos totalmente controlados. |
| **Nextcloud** (auto‑hosted) | Necesita servidor propio | Instalar en VPS, cliente de escritorio | Tiempo real, control total | Requiere más mantenimiento. |

### Recomendación principal: **Rclone + Google Drive** (o OneDrive si ya usas Microsoft)

- **Ligero**: solo se copia lo que cambie.  
- **Escalable**: funciona con cualquier tamaño de archivo dentro de los límites de la cuenta.  
- **Automatizable**: cron / Task Scheduler para sincronizar cada minuto o al detectar cambios.

## 3. Implementación paso a paso (ejemplo con Google Drive)

### 3.1 Instalar Rclone en el VPS

```bash
curl https://rclone.org/install.sh | sudo bash
```

### 3.2 Configurar el remote

```bash
rclone config          # sigue los prompts:
# 1) New remote
# name> gdrive
# Storage> drive
# (acepta los valores por defecto o configura tu propio client_id/secret)
# Autenticación → abre el enlace en tu navegador y pega el código.
```

### 3.3 Sincronizar la carpeta que sirve Nginx

Supongamos que Nginx sirve `/var/www/html`. Crea una carpeta local que será el “punto de entrada” para los archivos que subas desde tu PC:

```bash
mkdir -p /var/www/html/sync
sudo chown -R www-data:www-data /var/www/html/sync
```

Ejecuta una primera sincronización (una sola vez):

```bash
rclone sync /var/www/html/sync gdrive:/MiSitioWeb
```

### 3.4 Automatizar (cron cada minuto)

```bash
crontab -e
# Añade la línea:
* * * * * /usr/bin/rclone sync /var/www/html/sync gdrive:/MiSitioWeb --log-file /var/log/rclone-sync.log --log-level INFO
```

> **Resultado**: cada minuto Rclone compara la carpeta local con la carpeta en Drive y copia los archivos nuevos o modificados. Nginx sirve inmediatamente los cambios porque los archivos aparecen en `/var/www/html/sync`.

### 3.5 (Opcional) Sincronizar al revés

Si también quieres que los archivos que subas directamente a Drive aparezcan en el VPS:

```bash
* * * * * /usr/bin/rclone sync gdrive:/MiSitioWeb /var/www/html/sync --log-file /var/log/rclone-sync.log --log-level INFO
```

## 4. Alternativa “sin nube”: **Syncthing**

1. **Instalar** en VPS y PC (`sudo apt install syncthing` o descargar binario).  
2. **Crear carpeta compartida** (`/var/www/html/sync`).  
3. **Agregar la carpeta en la UI** de Syncthing (puedes acceder vía `http://localhost:8384`).  
4. **Escanear QR** o copiar la clave del dispositivo del VPS a tu PC.  
5. **Sincronización en tiempo real** → los archivos aparecen al instante en el VPS y Nginx los sirve.

> **Ventajas**: 0 latencia de la nube, datos nunca salen de tu infraestructura.  
> **Desventajas**: ambos extremos deben estar encendidos y conectados a la red (pero funciona perfectamente dentro de la VPN de Tailscale que ya usas).

## 5. Resumen de opciones

| Necesidad | Mejor opción |
|-----------|--------------|
| **Control de versiones + despliegues controlados** | Git + CI (GitHub Actions → `docker compose up -d --build`) |
| **Sincronización ligera y sin versionado** | Rclone + Google Drive / OneDrive (cron) |
| **Sin dependencia de terceros, tiempo real** | Syncthing (sobre Tailscale) |
| **Todo en tu propio servidor** | Nextcloud + cliente de escritorio |
