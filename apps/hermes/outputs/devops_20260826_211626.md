## 📋 Próximos pasos (borrador)

Una vez tengamos respuestas a las preguntas anteriores, el plan de acción típico sería:

1. **Seleccionar la plantilla/base**  
   - *Opciones con alta puntuación:*  
     - **JupyterHub + Theia** (⭐ ≈ 5 k) – permite notebooks colaborativos, ejecución de Python, y se puede extender con plugins para LaTeX y Excel.  
     - **Open edX + XBlock** (⭐ ≈ 3 k) – plataforma educativa con soporte para contenido estructurado por cursos y semanas.  
     - **Moodle + CodeRunner** (⭐ ≈ 2 k) – LMS con plugin para ejecutar código Python y almacenar archivos.  
     - **GitBook + Mermaid/LaTeX** (⭐ ≈ 4 k) – documentación estática que puede enlazar a recursos externos y soporta fórmulas.  
   - Evaluaremos cuál se adapta mejor a tu stack (React/Fastify + Docker) y a los requisitos de edición en línea.

2. **Diseñar la arquitectura de contenedores**  
   - Docker‑Compose con los siguientes servicios:  
     - `gateway-nginx` (puertos 8080/8443)  
     - `api-fastify` (REST/GraphQL) → gestiona metadatos de ramos, enlaces, autenticación.  
     - `frontend-react` (SPA) → editor de ejercicios (integrará **Monaco** + **Plotly** + **MathJax**).  
     - `jupyterhub` (opcional) → entorno Python para gráficos y notebooks.  
     - `postgres` + `redis` (persistencia y caché).  
   - Volúmenes persistentes para **uploads** y **repositorio de contenidos**.

3. **Implementar CI/CD**  
   - GitHub Actions que:  
     - Ejecuten linters (`eslint`, `flake8`), pruebas unitarias y de integración.  
     - Realicen escaneo de vulnerabilidades (`trivy`).  
     - Desplieguen a staging y, tras aprobación manual vía **Telegram Bot** (1‑click), a producción.  

4. **Gestión de archivos y deduplicación**  
   - Al subir un nuevo recurso, el backend verificará si ya existe mediante hash SHA‑256.  
   - Si el archivo ya está en la página de la universidad, se guardará solo el **enlace** (campo `external_url`).  
   - Se mantendrá un índice en Postgres (`files` table) con versión, hash y origen.

5. **Seguridad y variables de entorno**  
   - `.env` gestionado con **Vault** (HashiCorp) y referenciado en los contenedores vía `docker‑compose` secrets.  
   - JWT + HTTPS (Let's Encrypt) en Nginx.  

6. **Monitoreo y alertas**  
   - Health‑checks en cada contenedor → reportamos estado con emojis (`🟢`, `🟡`, `🔴`).  
   - Prometheus + Grafana para métricas; alertas a Telegram.
